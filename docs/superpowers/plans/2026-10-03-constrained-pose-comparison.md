# 受约束姿态比较：下一阶段

目标：对同一已生成STL，在固定的自动支撑虚拟配置下比较最多4个刚性姿态，报告几何、支撑、成本及用户保护体积风险。先用实际工具验证，再接AGH比较流程；不把无支撑基线或变形后的模型算成省料成果。

## 冻结协议

- 源模型与尺度不变；所有候选由同一STL SHA生成。姿态先限定[0,0,0]、[30,0,0]、[-30,0,0]、[0,30,0]度，最多4个，不扩大随机搜索。
- 旋转围绕原模型包围盒中心，再居中XY和Z-min=0；保存完整source-to-print 4×4矩阵与逆矩阵。不得假定变换后原图ROI或旧baseZ仍有效。
- 同一自动支撑配置 `fdm-pla-04-auto-support`：复制现有固定PLA/0.4喷嘴/0.2层高/2墙/15%填充配置，仅将support_material开启，保持auto/threshold=0等原配置；保留原始关闭支撑配置不变。
- 切片实际配置、源/候选STL与G-code分别计算SHA；固定床中心90,90，并核对实际平移。比较耗材与时间仅针对通过相同约束的候选，不承诺最优、等强度或实物可打印。
- 保护区域由原模型坐标中的用户确认AABB定义。第一版只报告支撑/接口挤出包络进入该保护体积的近似长度与次数，不能称真实接触面积、表面损伤或精确曲面保真。
- G-code先剔除travel、回抽、Z-hop、skirt/brim、模型路径及unknown role；扣除床平移，再逆刚性矩阵回原坐标。Support与interface分开报告；没有完整角色/变换/线宽证据时未验证，不能零风险。
- 无保护区域时仅比较成本，明确未验证关键区域；所有候选相同约束、允许无改善或全不可行。

## 并行模块与文件边界

1. `src/pose-geometry.mjs`与其测试，必要`tools/reconstruction/transform_pose.py`：固定文件输入、刚性变换、独立STL边界/体积/封闭核查；只写忽略的data内。
2. `src/support-evaluation.mjs`与其测试：复用parseGcodeSegments，原坐标保护体积近似支撑风险；斜姿态/平移/模型/回抽/unknown反例。
3. `src/slicer.mjs`、其测试、`tools/slicer/fdm-pla-04-auto-support.ini`：第二命名配置、SHA与支持参数安全摘要，默认原调用不变。
4. root完成脚本 `tools/compare-print-poses.mjs` 和 `docs/pose-comparison-2026-10-03.md`：先跑一个受控有真值几何，再用现有用户压力模型运行4姿态真实切片，保存完整公平比较，不重复生成大模型。

- [x] 模块red-green与几何/解析反例通过。
- [x] 相同STL用相同auto-support profile产生可复核G-code；基线与各姿态的input/source/配置SHA统一。
- [x] 原坐标ROI保持、逆变换与床平移验证；unknown不能作通过。
- [x] 总耗材/估时与支撑/ROI代理指标一起呈现；无保护区主张不越界。
- [x] 实际比较证明了保护约束会改变选择，因此接入独立AGH原生插件和受限UI；复杂支撑阻断、FEA与任意曲面重塑仍不在本阶段。
