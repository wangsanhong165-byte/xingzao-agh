# 平面细节切片验证（2026-10-02）

运行 `node tools/validate-planar-cases.mjs`，生成自制 PNG 图案，实际生成封闭浮雕 STL，调用 PrusaSlicer 2.9.6，并对真实 G-code 计算模型路径覆盖、外溢与孔洞余量。完整结果在忽略版本控制的 `data/print-validation/planar-cases/results.json`，图片与任务状态同时保存。

此批验证直接调用实际工具，调用来源记录为 `system`，**不属于 AGH 模型运行证据，不是照片重建测试，也不是实物打印验证**。

任务策略 `planar-path-v2`：目标模型路径覆盖 ≥90%；外溢路径面积/全部模型路径面积 ≤15%；保护孔洞剩余栅格面积 ≥80%且保持连通；至少两层真实模型浮雕路径。保真 IoU 门槛由用户确认的 `constraints.minFidelity` 决定，结果的 criteria 同步记录该值；**本批测试固定为 ≥0.85，不是所有任务的全局硬阈值**。宽深 40×30 mm、底厚 2 mm、虚拟 PLA / 0.4 mm 喷嘴 / 0.2 mm 层高，分别比较平板、0.2 mm 与 0.4 mm 浮雕。

| 样例 | 类别 | 0.4 mm 目标覆盖 | 实际结果 |
|---|---|---:|---|
| 圆环 | 正常 | 90.26% | 通过 |
| 字母 H | 正常 | 94.19% | 通过 |
| 两个独立图形 | 正常 | 95.85% | 通过 |
| 双孔图案 | 正常 | 96.73% | 通过 |
| 偏心局部 ROI | 边界 | 91.45% | 通过，原图位置保留 |

所有平板基线均未被当作细节保护成功；所有 0.2 mm 浮雕均因只有一层而未通过本任务策略。此处“通过”是限定虚拟配置和工程阈值下的结果，不代表图案在真实打印机上的视觉可读性。

## 本轮发现并修正的问题

最初解析器在每次 TYPE 变化时清空线宽，导致 H 和实心图形的部分模型路径被误判“线宽未知”。[PrusaSlicer 2.9.6 的 GCode.cpp](https://github.com/prusa3d/PrusaSlicer/blob/version_2.9.6/src/libslic3r/GCode.cpp) 中 TYPE 与 WIDTH 分别缓存；WIDTH 仅在宽度变化时输出。因此，本程序对本次固定版本的 PrusaSlicer G-code 保留 WIDTH 状态直到下一个 WIDTH；未知生成器继续采用保守策略，不推测缺失线宽。

修正前任务状态仍保留在对应 job 目录，没有把未通过的记录改写为通过。新增两条解析回归测试，分别验证已知版本的持久线宽与未知生成器的保守处理。

## 范围与局限

- 此验证只支持平面 XY 浮雕和用户确认的 ROI；暂不支持曲面、任意物体局部细节或强度判断。
- 路径覆盖是各浮雕层的 XY 合并投影，并非每一层的逐层保真或材料流动仿真。
- 线宽来自 G-code 元数据；栅格边界存在 0.1 mm 离散误差。
- 本轮样例为自制受控图案，没有真实照片质量波动；后续主案例仍需照片重建与导入的独立验证。
- 未降低验证门槛以提高通过率，也未把规则化浮雕当作专业人物建模成果。
