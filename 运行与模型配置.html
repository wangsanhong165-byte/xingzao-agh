从GitHub源码开始

先安装Node.js 24.10或更高版本（含npm），在克隆的仓库根目录执行npm.cmd ci。运行node tools/review/run.mjs复核仓库自带样例；运行npm.cmd start打开工作台。GitHub版本不附Node、Python环境、切片器二进制、模型权重或开发机任务数据库，所需工具由下文安装器下载。新任务需要配置本人的AGH账号与专业工具。

下文同时说明参赛包与GitHub部署：提到“完整源码”时，GitHub用户均指仓库根目录；提到“案例/测试样例”时，GitHub用户使用仓库根目录case/及examples/。参赛包独有的预装组件不作为源码克隆的前提。

所有功能最终都在同一个工作台 http://127.0.0.1:4337/ 使用。提交包完整解压后，先打开根目录 **README.html**。以下命令在 **完整源码** 根目录执行；GitHub用户在仓库根目录执行。

材料与运行入口

提交包根目录为README.html、演示视频.mp4、完整源码、AGH运行记录、案例。README.html包含材料链接；案例/index.html提供三类案例的输入、过程和交付文件。

以下命令均在 **完整源码** 目录执行；GitHub用户在仓库根目录执行。参赛包附Node及前端依赖，先为当前PowerShell设置路径：

$bundledNode = Join-Path $PWD 'data/tools/node-v24.16.0-win-x64'
if (Test-Path $bundledNode) { $env:PATH = $bundledNode + ';' + $env:PATH }

重新复核已有文件：

node tools/review/run.mjs

GitHub版本的报告写入仓库根目录复核报告.html；参赛包按随包目录生成报告。不调用模型，不需要Key或GPU。

启动工作台：

$env:PHOTO_CAD_AGH_HOME = Join-Path $env:USERPROFILE '.agh-print-detail-v2'
node src/print-server.mjs

地址为 http://127.0.0.1:4337/。新任务按后文配置AGH；图片建模和上色还需GPU环境及权重。

随包离线复核组件

200 MB以内的参赛补充包预装了 PrusaSlicer 2.9.6、CPU网格与刀轨复核所需的Python wheels，以及本机编译并可选使用的纹理扩展wheel。Windows x64、Python 3.12 用户可以直接安装CPU复核环境并离线运行切片，不必再从PyPI下载这组依赖。这个轻量环境用于网格和制造验证，不包含图片识别或生成所需的OpenCV、模型权重及GPU运行库。若从GitHub源码克隆，安装器可以在线下载同版本依赖及切片器。

py -3.12 tools/setup/reproduce.py environment --kind cpu-review
& .\data\reconstruction\env-torch-readonly\Scripts\python.exe tools/setup/check_runtime.py --kind cpu-review
py -3.12 tools/setup/reproduce.py assets --scope slicer

安装Python3.12 x64后，依次执行上面三条准备命令，再重新建模并切片：

& .\data\reconstruction\env-torch-readonly\Scripts\python.exe tools/setup/reslice.py

最后会打开“本次重新生成与切片”报告；新文件保存在源码 data/reproduction-runs/ 的本次目录。STL切片所需的PrusaSlicer exe和DLL保持官方字节，套件省略GUI示例资源和本项目不用的STEP导入库；安装器校验固定SHA-256，完整官方发行版与源码地址保留在ORIGIN.txt。完整图像建模和上色需要下载模型及GPU依赖，见第4步。

固定GPU路线为Windows x64、Python3.12、RTX5060 Laptop 8GB、Torch2.11.0+cu130。重新建立两个独立Python环境，不复制开发机的Conda或语音环境。

第1步：安装项目依赖与专业工具

打开PowerShell，进入源码目录：

参赛包已经附Node运行环境。使用下面命令前，可只为当前PowerShell设置路径：

$bundledNode = Join-Path $PWD 'data/tools/node-v24.16.0-win-x64'
if (Test-Path $bundledNode) { $env:PATH = $bundledNode + ';' + $env:PATH }
npm.cmd ci

py -3.12 tools/setup/reproduce.py assets --scope core
& .\data\reconstruction\env-torch-readonly\Scripts\python.exe tools/setup/check_runtime.py --kind cpu

安装过程的pip check应显示 **No broken requirements found**；最后应输出 **meshImport: true、imageProcessingAvailable: true**。安装器下载固定PrusaSlicer2.9.6和Hunyuan源码，核验哈希与53份源文件。它只准备项目data/，拒绝修改继承环境；遇到旧环境请用新解压目录。

只看计划而不安装：py -3.12 tools/setup/reproduce.py --plan assets --scope all。

第2步：构建AGH、配置账号、安装插件

powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/setup/agh.ps1 -Action Build
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/setup/agh.ps1 -Action Serve

Build获取AGH固定版本ec7ebbdb36e7658d2a121c3ba5113e850b16cb63，应用agh-adaptation/全部适配，使用pnpm10.34.5构建完整运行目录；pnpm通过npm临时调用。脚本拒绝覆盖不同版本源码或已有运行目录。

Serve终端保持打开，按终端地址进入AGH Provider设置。选择 **CommandCode**，Base URL为 https://api.commandcode.ai/provider/v1；输入本人Key，测试连接，选择 **deepseek/deepseek-v4.1-flash**，保存为默认账号。项目也支持Agnes AI的agnes-3.0-flash；其他模型需修改并验证项目路由白名单，不能只填任意名称。

另开PowerShell进入同一源码目录，停止此专用AGH实例，再安装四个业务插件：

$env:AGH_HOME = Join-Path $env:USERPROFILE '.agh-print-detail-v2'
$env:PHOTO_CAD_AGH_HOME = $env:AGH_HOME
$env:AGNES_PROFILE = 'local-dev'
node data/agh-runtime/agnes.mjs daemon stop --profile local-dev
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/setup/agh.ps1 -Action Plugins
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/setup/agh.ps1 -Action Serve

插件安装从随包源码读取真实integrity，通过AGH官方安装、信任、启用、快照固定流程准备姿态、修正、重建和上色工具。Key只保存于本人AGH私有凭据库，无需开发者Key、.env或历史账号。

第3步：先跑CPU制造任务

启动工作台并完成AGH配置后，可用随包灯柱验证完整任务：

1. 首页进入“细杆检查”，点击“导入自己的STL / GLB”。选择提交包 案例/测试样例/case/source-original.stl；GitHub用户选仓库 case/source-original.stl。

2. 将“目标最长边”填为 **30 mm**，点击“检查并导入模型”。应显示尺寸 **12 × 8 × 30 mm**，再点击“继续细杆检查”。

3. 杆轴选择 **Z轴**，保留默认预算 **0.2 mm径向、20 mm³新增体积**。先在模型画布上滚轮放大，再点“点击模型选取细杆”，点击杆身中段。

4. 查看测量提案，应得到 **0.25 mm半径**和 **Z=2到28 mm**的完整轴线。勾选确认后，点“开始一次打印方案检查”。

5. 等待五姿态比较和结果重检。成功时本页开放STL下载；点击“查看姿态任务”，在结果页下载 **已验证G-code**。任务地址可用于恢复查看。

AGH组织姿态比较，工具实际生成G-code；原件可行便直接交付，必要且预算允许才修正。结果页显示特征/连续性检查、采用方案和耗材/时间估算，可下载模型和刀轨。降低预算或改变目标可以查看停止结果。

node tools/review/preflight.mjs --mode offline
node tools/review/preflight.mjs --mode live

offline应为ready，live还需账号与插件就绪。实际成功以任务页工具结果和文件交付为准。

py -3.12 tools/setup/reproduce.py environment --kind gpu
& .\data\reconstruction\env-torch-readonly\Scripts\python.exe tools/setup/reproduce.py assets --scope shape

第5步：编译上色扩展

**GitHub源码克隆不附预编译wheel，请直接执行下方“从开始菜单打开 x64 Native Tools”后的源码构建命令。** 只有另外持有同平台参赛补充包wheel时，才使用下面的可选预编译安装命令。

针对 RTX5060 Laptop / Windows x64 / Python3.12 / Torch2.11.0+cu130，补充包已带两个编译好的wheel。在GPU环境和Hunyuan源码装好后，可执行以下两条，符合该配置即可跳过源码编译。其他CUDA、Torch或GPU组合请用后面的源码构建步骤。

data\reconstruction\env-texture-probe\Scripts\python.exe -m pip install --no-index --no-deps --find-links data\setup\wheels custom-rasterizer==0.1 mesh-processor==0.0.0
data\reconstruction\env-texture-probe\Scripts\python.exe tools\setup\check_runtime.py --kind texture --gpu-smoke

检查应显示 nativeExtensions: true 且 rasterVisiblePixels 大于0。

从开始菜单打开 **x64 Native Tools Command Prompt for VS2022**，进入源码目录。以下是CMD命令，CUDA目录按实际安装路径设置，变量仅影响当前终端：

set "CUDA_HOME=C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v13.0"
set "CUDA_PATH=%CUDA_HOME%"
set "PATH=%CUDA_HOME%\bin;%PATH%"
data\reconstruction\env-texture-probe\Scripts\python.exe tools\setup\build_native.py
data\reconstruction\env-texture-probe\Scripts\python.exe -m pip install --no-index --no-deps --find-links data\setup\wheels custom-rasterizer==0.1 mesh-processor==0.0.0
data\reconstruction\env-texture-probe\Scripts\python.exe tools\setup\check_runtime.py --kind texture --gpu-smoke

脚本在副本中构建custom_rasterizer和mesh_processor，携带已验证的Windows编译设置，目标sm_120。固定上游版本已包含int64_t修复，无需改动受哈希保护的生产源码。最后应输出 **textureImport: true、nativeExtensions: true、rasterVisiblePixels大于0**。失败时核对VS、SDK、nvcc和Torch版本，保留错误输出。

两个环境均不继承系统包：

  • 形状/几何：data/reconstruction/env-torch-readonly/Scripts/python.exe
  • 上色：data/reconstruction/env-texture-probe/Scripts/python.exe

第6步：从输入到交付

保持AGH Serve和工作台进程运行，在4337首页操作：

1. **照片建模**：上传正、侧、背图，确认侧视方向与尺寸；等待白模、网格检查和初次切片。

2. **彩色审阅**：从同源模型进入上色，上传插画参考，查看GLB配色和接缝。这一步可选，制造用源几何保持独立。

3. **外观保护**：点选重要表面、调整保护体积、确认目标；AGH比较五姿态，列出局部支撑收益和总耗材/时间代价。

4. **细杆检查**：点选直圆杆、确认预算，按反馈保留原件或受约束修正；失败条件会停止。

5. **文件交付**：在结果页下载模型和刀轨；保存任务URL可恢复现有任务。

各入口携带模型来源，均在同一工作台。可使用本人图片；GitHub的case/skull-input-front.png、skull-input-left.png、skull-input-back.png提供公开许可三视图，来源在case/skull-input-manifest.json；提交包保留对应真实刀轨供复核。

新任务数据在项目data/目录，例如reconstruction/jobs（建模）、texture（上色）；制造结果由页面提供下载。新AGH记录在本人专用home，通过Web导出，或在PowerShell中：

$env:AGH_HOME = Join-Path $env:USERPROFILE '.agh-print-detail-v2'
$env:AGNES_PROFILE = 'local-dev'
node data/agh-runtime/agnes.mjs sessions --json
node data/agh-runtime/agnes.mjs export <实际会话ID> --format agnes --html

pip依赖批量下载与离线安装

按pip download官方流程下载安装文件，不复制site-packages：

py -3.12 tools/setup/reproduce.py wheels --kind gpu --destination data/setup/wheels

该目录收集Torch和项目Python依赖；第5步的两个原生wheel也在同一目录。相同平台的另一台机器，可在新解压源码中：

py -3.12 tools/setup/reproduce.py environment --kind gpu --wheelhouse data/setup/wheels
& .\data\reconstruction\env-texture-probe\Scripts\python.exe -m pip install --no-index --no-deps --find-links data/setup/wheels custom-rasterizer==0.1 mesh-processor==0.0.0

Git/Node/VS/CUDA、AGH构建依赖、模型和切片器不是pip，仍按前面步骤准备。原生wheel适用相同Python/Torch/CUDA/GPU架构，其他平台需重新编译。

视频和trace保留已有任务记录；重新执行会产生新的模型、刀轨和AGH记录。
